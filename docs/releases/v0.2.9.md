# MikuBox v0.2.9

本版做两件事:把「连接出问题」翻译成人能读懂的日志和提示,以及堵住隧道在用户不知情时被自动拉起的三个漏洞。

## 出口诊断

- 出口 IP 探测失败时,日志不再只有一句 warning:同一行里写明探测路径(核心本地入口 / 设备自身网络)、当时隧道状态(running / connecting / down)与每个端点的具体失败原因(超时、连接被拒、无法解析等)。`tunnel=running` 且全部超时,说明出口节点/链路死了;`path=device network` 且 `tunnel=down`,说明应用当时没有承载任何流量,网络问题与本应用无关。
- 通知栏出口行:连续 3 轮探测失败(约一分钟)后由「…」变为「出口无响应」,并记录一次性告警——节点挂掉不会再伪装成正常连接。
- 按需分流自动连接/暂停时写入日志,后台拉起隧道从此可归因。

## 修复:隧道不再不知情地自动出现

- 手动连接失败后,后台不再于约半分钟后静默重试:失败即保持断开。守卫的退避重试只保留给进程死亡后的自动恢复,三振熔断不变。
- 重启手机或强行停止应用后,隧道不再自动复活;是否连接完全由「开机自动连接」开关与用户操作决定。进程被系统杀死时守卫照常恢复,该能力不受影响。
- 「启动时自动连接」只在真正打开应用(启动页全新创建)时生效:后台任务、广播、快捷设置磁贴绑定不再触发连接,手动断开后切回应用也不会被重新连上。

## 其它

- 启动页:UI 设置里的启动页开关此前是摆设(开关打开也不显示),现在它真实控制参考版启动页的显示,默认仍为关闭。

## 验证

72 项单元回归通过;`assembleRelease` 本地签名构建通过,证书指纹 60e6a6a6…。守卫/自动连接的期望分支依赖 MMKV,本地单元测试环境不可达,以编译与代码评审覆盖;建议真机确认两点:连接坏配置失败后不再自动重试;重启后(开关关闭)约半分钟内不再自动连上。
