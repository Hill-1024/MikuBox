# MikuBox v0.2.10

本版处理「连接中断/在错误时刻自主唤醒」：堵住几条会让隧道在用户不知情时自己起来的路径，并让每一次启动、停止都能在日志里直接归因。

## 修复:隧道不再自行复活

- **应用更新不再等于开机自启**。`MY_PACKAGE_REPLACED` 过去会走完整的「开机自动连接」流程，安装新版本后一分钟内隧道自己连上；现在更新只刷新订阅调度，是否连接由「开机自动连接」开关和用户操作决定。
- **手动断开后，冷启动不再被「启动时自动连接」连回**。新增持久标记，手动停止时写入、用户下次主动连接时清除；开启自动连接的用户在主动断开后重新打开应用仍是断开状态。
- **停止后 1.5 秒内的启动被忽略**。此前的日志里出现过 STOP 之后约 1 秒又出现一次无 action 启动的形状（重复手势、延迟的自动化、界面事件），现在普通启动会在这段窗口内被拒绝；守护恢复与系统「始终开启的 VPN」不受影响。
- **停止过程中发起的连接被忽略**，不会在隧道还在拆除时反向拉起。
- **未知/过时的 action 不再启动隧道**；`REFRESH_VPN`/`RESTART_VPN` 落到没有隧道的服务时直接停掉空服务，不再留下可被系统复活的实例。

## 诊断:启动来源可读

服务命令日志现在一次写明：

```
service command action=... source=ui startId=1 expected=false running=false starting=false
```

`source` 取值包括 `ui`、`tile`、`boot`、`guard`、`on-demand`、`notification`、`launch-auto`、`system-sticky`、`system-always-on`。没有 action 的启动只可能是系统粘性重启；普通启动使用显式的 `START_VPN`，两者不再混在同一行日志里。停止命令同样带来源，连接中断可以直接看出是谁停的。

> 提示：应用内日志级别默认是 `warning`，上述 `info` 行需要把「核心设置 → 日志级别」调到 `info` 才会出现在 logcat。

## 其它

- 桌面静态快捷方式（切换/启动/停止/扫码）的 `targetPackage` 误写为参考版的 `com.miku.ray`，点击无反应；已改为本应用包名。
- 页面背景色改用 `colorSurfaceVariant`，与卡片层级拉开对比。
- 出口探测随隧道启停一并取消：停止后不会再出现连向已关闭本地入口的 `ConnectException`，新连接也不会被上一轮的探测结果污染。
- Tasker/自动化触发的停止入口会校验 Locale `FIRE_SETTING` action 与开关字段，空广播或转发的 intent 不再被误读为「断开」；清单同时声明了该 API 的标准权限。

## 验证

`assembleDebug` + 单元回归通过（构建号 210）。模拟器验证：安装更新后 25 秒内无服务启动；开启「启动时自动连接」时，手动停止后强制停止再冷启动仍保持断开，手动点击连接可正常恢复。启动来源与 1.5 秒停止宽限属于服务内状态，依赖 MMKV/Android 服务环境，本地 JVM 测试不可达，以编译与模拟器行为覆盖。
